First Choose your model
Before you download anything, learn to read a model name — then you pick the one that fits your computer.
Model names look scary, but each part tells you one thing. Here's an example — read it left to right:
qwen2.5 : 3b - instruct - q4_K_M
qwen2.5Family & version — who made it & which release. (This one's Qwen, by Alibaba — but it could be Llama, Gemma, Mistral, Phi…)
3bSize — how many "brain cells" (parameters).
instructFlavor — trained to follow your instructions & chat.
q4_K_MQuantization — how compressed the file is.

Almost every model — Qwen, Llama, Gemma, Mistral — follows this same pattern. Learn it once, read them all.

1 · Size — what is "2B / 3B / 7B"?

B = billions of parameters — the model's adjustable knobs. More knobs = more knowledge, but a bigger download and slower replies. Think engine size.

S
1B–3B

Small & fast. Runs on almost any laptop. Safest pick for camp.

M
7B–8B

Smarter, needs a decent machine (~8GB+ RAM). The popular sweet spot.

L
13B–70B+

Very capable, but heavy — usually needs a strong GPU or a server.

Rule of thumb: pick the biggest model that still feels fast on your computer.

2 · Flavor — "instruct" / "base" / "chat"
★
instruct (or chat)

Trained to follow instructions and hold a conversation. This is what you want for a chatbot. Pick this one.

○
base

Raw text-completion only — it just continues your text, it doesn't "answer". For researchers/fine-tuning, not chat.

Other tags you'll see: code (tuned for programming), vision / VL (can read images), R / reasoning (thinks step-by-step).

3 · Quantization — "Q2 / Q4 / Q8"

Quantization shrinks the model so it fits & runs on normal computers. The number is roughly the bits per knob: lower = smaller & faster, but a little less accurate. Like saving a photo as JPG — smaller file, slightly less detail.

Q2 / Q3Tiniest & fastest, but noticeably "dumber". Only if you're tight on space.
Q4The sweet spot — small & fast, still smart. The usual default.
Q5 / Q6A bit bigger, a bit sharper. Nice if you have the room.
Q8Almost identical to the full model. Largest of the quantized set.

The extra letters (K_M, K_S) are just smarter compression recipes — M = medium, S = small. Don't overthink them.

No Q tag at all? Ollama just picked a sensible default (usually Q4) for you.

Your turn — pick one

Browse what's available at ollama.com/library →, then choose using the pattern above. A safe formula for most laptops:

a 1B–3B · instruct · Q4 model
Not sure? qwen2.5:3b is a great default for today — but llama3.2:3b, gemma2:2b or phi3:mini work too. Your camp, your call.

Hour 2 Run it locally
Talk to your AI on your own machine — no internet needed.
1
Start Ollama the right way

Open a terminal in the project folder and run the bundled script. It clears anything stuck on the port and starts the server with browser access enabled. Leave that terminal open.

./start-ollama.sh

(You can also just double-click the file.) Prefer typing it yourself? This is the same thing in one line:

pkill -f ollama; OLLAMA_ORIGINS=* ollama serve
2
Why that command and not just "ollama serve"

Opening the Ollama app alone is not enough. A browser refuses to talk to a server that hasn't said it's allowed — that permission is OLLAMA_ORIGINS. Without it the app loads fine but every message fails.

3
Skip this step forever (optional)

Did the Pre-install step for this? Then you can ignore the script entirely — opening the normal Ollama app is enough. If not, run this once and restart Ollama; the permission sticks from then on.

echo 'export OLLAMA_ORIGINS="*"' >> ~/.zshrc
4
Test it in the terminal

In a second window, type a message and see it reply. Type /bye to exit. (Use your own model name in place of the example.)

ollama run qwen2.5:3b
5
Serve the app

In a third terminal, from the project folder. Do not double-click index.html — opened that way the browser blocks parts of the app.

python -m http.server 8000

Then visit http://localhost:8000. (VS Code's Live Server extension does the same job with a right-click.)

6
Check you're connected

The chip at the top-right should say Ollama with a green dot. In the sidebar, Sources already has a document loaded — that's the reference material your AI can quote from.

7
Send your first message

Pick the model, type "Kumusta!" and watch it reply word-by-word.

!
Stuck? "Port already in use" / "address already in use"

Something is already sitting on port 11434 — almost always an Ollama that started quietly in the background without browser access. It must be stopped before a new one can take the port. Run this, then start again:

pkill -f ollama

The same fix applies when the app says "Ollama isn't allowing browser requests" even though Ollama is clearly running — that's the stale one answering.

Connect a Model
Add another model to this app — a second local one, or a cloud provider. Open the model picker at the bottom of the chat and click Add Models (or → Model).
Anything you add here is saved in this browser only — it makes your copy work, not your published one. The live site gets its model from a Vercel environment variable instead — see the Publish tab.
1
Understand the two cards

The dialog has a LOCAL card (for Ollama on your machine) and an API card (for a cloud provider). For a live site you want the API card.

Any OpenAI-compatible endpoint works — that's why one dialog fits them all.

2
Pick a provider

Use the dropdown on the API card — DeepSeek, OpenAI, Together, Groq, or Custom. Choosing one auto-fills the endpoint URL for you. Pick Custom to paste your own.

https://api.deepseek.com/v1
3
Paste your API key

Get a key from the provider's dashboard and paste it in the API key field. The key is stored only in this browser — it never gets committed to your repo.

4
Test, then Add

Click Test to confirm the endpoint is reachable (it pings /models). Then click Add — the app auto-discovers every model the endpoint offers and lists them. If a provider hides its model list, it falls back to a sensible default (e.g. deepseek-chat, gpt-4o-mini).

5
Select your model & manage endpoints

Open the picker again and choose the new cloud model — the header chip updates to show it. Under Added Models you can enable/disable individual models or remove an endpoint. Your added endpoints are saved and survive reloads.

6
Adding a custom LOCAL endpoint

Running Ollama (or any OpenAI-compatible server) on another port or machine? Use the LOCAL card and paste its URL — e.g. http://localhost:11434/v1 — add an optional key for protected servers, then Add. Same Test → Add flow.

Hour 4 Share it with a link
Your AI already works — free and private, on your own machine. This last hour just proves it to the world.
Finish customizing first — that's the version the world will see.
1
Publish your AI

Everything you set up lives in this browser — that's why it's private, and why pushing your code alone would deploy the blank starter app instead of yours. Settings → Publish → Download my-ai.json, then drop that file into your project folder beside index.html.

2
Save & upload with Git git add . git commit -m "Publish my AI" git push
3
Import into Vercel

On Vercel: Add New → Project, pick your repo, click Deploy. No config needed.

4
Get your own free model key

Visitors can't reach the Ollama on your laptop — so the live copy borrows a hosted model. Sign up at console.groq.com → (free, no card) and create the key on your own account. It stays yours: every message a visitor sends spends a little of your free daily allowance, and when that runs out your link goes quiet until it resets. Keep the key to yourself — sharing the link is the point, sharing the key never is. Any OpenAI-compatible provider works if you already have one — but DeepSeek needs paid credits, so don't start there today.

5
Add the key to Vercel — not to your code

On your project: Settings → Environment Variables → add MODEL_API_KEY with your key → Redeploy. Never paste a key into a file you commit: your repo is public, and keys in public repos get found and drained within hours.

6
Open your URL and share it

You get a public link like your-ai.vercel.app. Anyone can chat with your AI — your name for it, your personality, your uploaded knowledge — and nobody but you can change what it is.

7
Open your first Pull Request

On GitHub, open a PR from your fork. Your first open-source contribution — on record forever.

Remember which one is the real one. The shared link runs on somebody else's computer, on a hosted model metered against your own key. The AI on your machine is the one that's free, offline, and private — nobody can meter it, price it, or switch it off. That's the one you actually built today.

Glossary — tap to expand the words you'll hear today
AI
A program that learns patterns from data and uses them to answer questions or generate text. Like autocomplete, but really, really good.
LLM
Large Language Model. The AI's brain — trained on billions of sentences to predict what word comes next. Like a student who has read every book in the library.
Qwen
The specific AI model you're using today — made by Alibaba, free and open source, small enough to run on this computer. Like a free, downloadable brain.
Ollama
Software that runs AI models on your own computer without needing the internet. Like VLC for video — but for AI models.
API
Application Programming Interface. A way for two programs to talk to each other. Your chat app sends a message to Ollama's API, Ollama asks Qwen, Qwen replies. Like a waiter — you don't go to the kitchen, you order through the waiter.
Terminal
A text window where you type commands directly to the computer. No clicking — just typing instructions. Like texting your computer instead of tapping buttons.
GitHub
A website where developers store and share code. Think of it as Google Drive for code — but with version history and collaboration tools. Your code lives here. Anyone can see, fork, and build on it.
Fork
Making your own copy of someone else's code on GitHub. You can change it however you want without affecting the original. Like photocopying a recipe so you can add your own twist.
Pull Request
A way to suggest your changes back to the original project. The project owners review it and decide whether to merge it in. Like submitting a revised chapter to an editor.
Vercel
A free hosting service. Connect your GitHub repo and it automatically gives your app a live public URL anyone can visit. Like publishing your website in 60 seconds.
Open Source
Code that anyone can read, use, and improve for free. No hidden parts, no fees. Like a recipe published in a community cookbook — anyone can cook it, improve it, and share it.
Streaming
Why the AI types word-by-word instead of all at once. The response is sent live as it's generated. Like watching someone type a reply in real time, not waiting for them to hit send.
System Prompt
A hidden instruction you give the AI before the conversation starts. It shapes the AI's personality, role, and behavior. Like a job description you give a new employee on their first day.
localhost
A special address that means "this computer." When you visit localhost:11434, you're talking to a server running on your own machine, not the internet. Like calling your own phone — you're not calling someone else.
git push
A command that uploads your local code changes to GitHub. After this, your code is online and Vercel can pick it up. Like hitting "sync" to upload your work to the cloud.
Frontier AI
The most powerful, cutting-edge AI models in the world — like GPT-4 or Gemini Ultra. They require massive computers and cost millions to run. Like a Formula 1 car — incredible, but you can't park it in your garage.
Lightweight
A small AI model designed to run on regular hardware — like your laptop or school computer — without needing a powerful GPU. Qwen 2.5 3B is lightweight. Like a motorcycle instead of a truck — less power, but you can actually own and drive it.
Hallucination
When an AI confidently states something that is completely wrong or made up. It doesn't know it's lying — it's just predicting plausible-sounding words. Like a student who didn't study but still writes a very convincing wrong answer.
Parameters
The numbers inside an AI model that were learned during training. More parameters usually means smarter — Qwen 2.5 3B has ~3 billion of them. Like the billions of neural connections in a human brain.
Training
The process of teaching an AI by feeding it huge amounts of text and adjusting its parameters until it gets good at predicting language. Qwen was trained by Alibaba. Like studying for years before you can do a job — we skip this part and use the already-trained model.
Inference
When a trained AI model actually runs and answers questions. This is what happens when you send a message — the model is doing inference. Training is studying. Inference is taking the exam.
Token
The basic unit an AI reads and writes — roughly a word or part of a word. AI models think in tokens, not letters or sentences. Like how a song is made of notes, not just "music" as one thing.
Context Window
How much text an AI can "see" at once — its short-term memory for a conversation. Once the conversation is too long, early parts get forgotten. Like a whiteboard — once it's full, you have to erase something to write more.
Quantization
A technique that shrinks an AI model's file size by storing its numbers less precisely — trading a tiny bit of quality for much lower memory use. Like compressing a photo to JPEG — slightly lower quality, but 10x smaller file.
GPU
Graphics Processing Unit. A chip originally built for games that turns out to be perfect for running AI — it can do millions of math operations in parallel. Like using a 100-lane highway instead of a single road.
Prompt
The message or question you type to the AI. How you write it matters a lot — a well-written prompt gets a much better answer. Like asking a question in class — "explain gravity" vs "explain gravity using a basketball analogy for a Grade 7 student" gets very different answers.
RAG
Retrieval-Augmented Generation. A technique where you feed the AI extra documents before it answers, so it can give more accurate, specific responses. Like an open-book exam — the AI can look things up before answering.
Deployment
Publishing your app so other people can use it — not just on your machine. Today you deploy to Vercel so anyone with the link can use your AI. Like moving from cooking for yourself to opening a carinderia.
